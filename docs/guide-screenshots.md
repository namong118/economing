# GUIDE 페이지 스크린샷 캡처 기록

앱 화면이 바뀌면 해당 컷만 다시 캡처. 파일명 동일하게 덮어쓰기.

---

## 캡처 조건

- **뷰포트 폭 430px** — 앱이 모바일 우선 설계라 모바일 화면이 자연스럽게 나옴
- **로컬 dev 서버**에서 캡처 (`npm run dev`, 예: `http://localhost:5178/economing/#/경로`).
  배포 사이트는 캐시 때문에 최신 화면이 아닐 수 있어 사용하지 않음
- **실제 로그인 계정**으로, 학습 기록이 어느 정도 쌓인 상태에서 캡처
  (진도 0/96이면 빈 화면처럼 보여서 앱의 실제 사용 모습이 안 드러남).
  이번 캡처 시점 계정 상태: 잎 단계 · 70 XP · 학습 진도 19/96 · 3일 연속 학습 중
- 각 화면의 **가장 특징적인 부분**이 보이도록 스크롤 위치 조정
- 저장 위치: `public/guide/`
- 파일 형식 PNG

## 캡처 방법 (재현용 메모)

브라우저 확장의 `resize_window` 도구는 요청한 폭대로 뷰포트를 바꿔주지 못해 신뢰할 수 없음.
대신 아래 방식을 사용:

1. 새 탭(또는 기존 탭)에 `position:fixed; top:0; left:0` 래퍼 div를 주입
2. 그 안에 `width:430px; height:932px`인 `<iframe>`을 넣고 `src`를 캡처할 로컬 경로로 지정
3. 화면 상태(로그인, 스크롤, 클릭 등)를 iframe 안에서 준비
4. 브라우저 스크린샷 도구의 `zoom` 기능으로 iframe이 차지하는 영역만 잘라 `save_to_disk`
5. 저장된 임시 파일을 `public/guide/파일명.png`으로 복사

**주의**: `zoom`의 캡처 영역은 브라우저 창 폭(`window.innerWidth`)에 따라 실제 저장되는 픽셀
크기가 달라진다. 10장을 나눠서 찍으면 창 크기가 그 사이에 바뀌어 파일마다 해상도가
미묘하게 달라질 수 있음 (실제로 이번에 3장 정도가 384×840, 나머지가 427×932로 갈려서
전부 같은 세션 안에서 다시 찍어 427~430 × 931~932로 통일했음).
**한 번에 몰아서, 창을 리사이즈하지 않고 연속으로 찍을 것.**
